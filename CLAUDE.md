# Scare Your Neighbor — BACKEND (game server)

Frontend (3D client) lives at `../Scare-your-neighbor`. Colyseus + Mongo. (Ported from the Bowling Roll / boat-race server: the boat, race, spin and daily-reward parts were removed because the client has no such features.)

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, base, pose, loadout, avatar })`). **Room size = number of player bases**: `ROOM_MAX_CLIENTS` (`src/constants.ts`) = 11 = the client's `BASES.plots.length` (5 south + 3 east + 3 west). Keep them equal; the deploy workflow reads that line and sends it as `roomSize` (valid 2-100, no `seatCap`). Each player gets one base: roster `base` = lowest free index, or the `base` the client asked for if free (`assignBase`, presence.ts); freed when the player really leaves.
- Client-authoritative: the server only bounds/sanitises (`src/sanitize.ts`, `src/presence.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc is the player's only save. A guest's progress lasts the page only.
- Messages client -> server: `saveProgress` (whole snapshot, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out), presence (below), `adGift` (below). Server -> client (private): `progress` (saved doc, sanitized), `noProgress` (new account / guest / no DB), `serverError` (save unreadable: saving stays off), `leaderboard`, `giftResult`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted.
- Saved progress (`PlayerDoc`, client `src/net.js` stores): `money`, `speed`, `scareLevel`, lifetime stats `earned` / `scares` / `steals` / `playtime` (`$max`, so a stale save never lowers a leaderboard place), `auras[]`/`aura`, `costumes[]`/`costume` (worn id must be owned, "" = none), `lastSeen`. Server-only field: `giftAt`.
- **Presence** (`src/presence.ts`, `test/Presence.test.ts`): what the others draw, relayed through the roster `PlayerState` (schema in `rooms/schema/WorldState.ts`), only bounded. `pose` { x, y, z, yaw, speed, vy, grounded, stunned } (~12/s), `loadout` { aura, costume, hold } (`hold` = "" | `pkg:<kind>` | `item:<name>`: the stolen package / base item in the right hand), `setAvatar` { avatar } (Bloxity look JSON `{ equipped, proportions, skin }`, never parsed), `emote` { id } (roster `emote` = "<id>#<n>", "" = stopped; the client replays the Bloxity emote clip), `uid` (Bloxity user id, "" = guest: matches a Bloxity chat message to its sender so the bubble floats over the right player), `pfp`, `base`.
- **Neighbour animations** (`state.houses`, `HouseState`): the player who knocks on / scares / steals from a North Lane house is its driver; the client runs the neighbour state machine and sends `house` { i, state, pose, face, x, z, facing, speed, held, pkg, door, emoji, bubble, red, say } (~10/s) and `houseEnd` { i }. Everyone else plays that animation (door, model, face, package on the step, chase, speech bubble) instead of their own. One driver per house (updates from others are ignored); entries are dropped on `houseEnd`, when the driver leaves, or after `NEIGHBOUR_STALE_MS` without updates. Enums (`NEIGHBOUR_STATES/POSES/FACES`) and text length are validated.
- **Leaderboards** (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): the plaza board's game pages. Top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`earned`, `scares`, `steals`, `playtime`), one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). `leaderboard` { boards: { stat: [{ name, value }] }, ranks } is sent after each load and every `LEADERBOARD_EVERY_MS`. The Bloxity side (`Legion.SDK.leaderboard`) is submitted from the client (`src/leaderboards.js`); ids match `LEADERBOARD.bloxity` in the client config.
- **Free Gift = rewarded ad** (`src/ads.ts`, `adGift` in WorldRoom, `test/Gift.test.ts`): the client plays `Legion.SDK.ads.showRewarded` and, on `completed`, sends `adGift` { token }. The server verifies the token with Bloxity (`POST {BLOXITY_API_URL|https://api.bloxity.io}/v1/ads/reward/verify { gameSlug, rewardToken }`, slug = `BLOXITY_GAME_SLUG` or the injected `BLOXITY_GAME_ID`; a token verifies once), rejects another player's ad, enforces `AD_GIFT_COOLDOWN_MS`, stores `giftAt`, and answers `giftResult` { ok, amount (`AD_GIFT_MONEY` = 100), nextAt, serverTime } or { ok: false, reason: "invalid" | "cooldown" | "busy" }. The client grants the money only on ok. Outside production the token `dev-token` (the client's simulated dev ad) is accepted.
- **Base + Offline Money** (`PlayerDoc` `income`, `pile`, `baseLevel`, `slotsBought`, `boothLevel`, `millLevel`, `baseItems[]`, `basePackages[]`; `sanitize.ts`): the client saves its base (floor items / packages, levels) with the income rate in $/s. The server stamps `lastSeen` on load, on every save and when the player leaves; on load it sends `progress` with `offline` = income x seconds away (capped at `OFFLINE_MAX_SECONDS`, 24 h) and `away`, then re-stamps so the time is counted once. The server does NOT add it anywhere: the client puts it in the base's pile (`pile`, saved) and the player collects it. Roster `plot` (message `plot`, JSON string, capped by `PLOT_MAX_LEN`) is the compact base snapshot the other players draw on that plot.
- `src/constants.ts` bounds must cover the client's `src/config.js` (ids match `ID_PATTERN`). A contract change goes in both projects.
- **Bloxity room directory** (`src/legion-room-reporter.ts`, started from `src/index.ts` after `listen`): every ~2 s posts this pod's rooms to the matchmaker (`MATCHMAKER_REPORT_URL`, `BLOXITY_REPORT_TOKEN`, `BLOXITY_GAME_ID`, injected by Legion) so Open Rooms / friend joins / join-by-id show them; a no-op locally.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS`. Needs repo var/secret `LEGION_GAME_ID` and secret `LEGION_DEPLOY_TOKEN`. Legion injects `PORT`, `MONGODB_URI`, `CLIENT_ORIGIN`, `BLOXITY_GAME_ID`.
